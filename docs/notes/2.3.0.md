## Nouveautés

### Réappliquer ce qui est déjà en place

Quand l'analyse trouve que tout est déjà réglé, Sindry ne vous renvoie plus simplement à
l'accueil : « Réappliquer quand même » rend ces réglages cochables. Cochez ce qu'il faut
refaire, puis lancez. Rien n'est coché à votre place. Le même bouton existe en mode Expert,
en tête de l'analyse.

Les réglages d'une liste (« Améliorer la barre des tâches », par exemple) s'affichent
désormais « À faire » ou « Déjà en place », y compris en mode Simple, où ils n'apparaissaient
pas.

### Un échec, enfin expliqué

- La raison d'un échec s'affiche sous le nom de l'action, dans le bilan, même quand le
  script n'a pas de code d'erreur pour elle.
- Le titre du bilan suit l'issue : « Terminé, avec des échecs » ou « Rien n'a abouti »,
  plus « C'est terminé ! » quand rien n'a marché.
- Réglage 5.7, « Journal de diagnostic » (Expert) : les actions écrivent le détail de leurs
  erreurs dans le journal. À activer le temps de comprendre un échec. L'historique passe en
  5.8.

### Des journaux qui disent ce qui a tourné

- Les fichiers journaux portent le nom du script (`…_705_IMPROVE_TASKBAR.log`), plus un
  identifiant illisible.
- Dans le panneau Journal, chaque action commence par une ligne : son titre, son fichier, sa
  version.
- Les accents des messages d'erreur de Windows ne devraient plus arriver cassés.

### Pour les auteurs de scripts

- Dans un `catch`, écrivez le code, la cible et le type d'erreur ; la fonction `Write-Diag`
  détaille l'erreur quand `SINDRY_DIAG=1`.
- Une action doit accepter un élément déjà en place (`state=ok`) : l'utilisateur peut le
  réappliquer.
- Guide pour IA : règles 45 et 46, entrée 2.3.0 de `SCRIPTS_POUR_IA_NOUVEAUTES.md`.
- Détails dans `docs/FORMAT_SCRIPT.md`, « Expliquer un échec ».
